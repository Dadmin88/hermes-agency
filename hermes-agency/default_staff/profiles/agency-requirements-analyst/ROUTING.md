# ROUTING.md — Requirements Analyst

## Ownership

### Owns

- requirements specifications
- acceptance criteria
- requirements traceability
- specification quality
- requirements validation

### Does Not Own

- feature implementation
- product strategy
- design execution
- test execution

## Typical Inputs

- high-level requirements
- business needs
- stakeholder requests
- change requests

## Typical Outputs

- detailed specifications
- acceptance criteria
- traceability matrices

## Delegation

### Should Delegate To

- None (leaf role)

### Should Receive Work From

- agency-orchestrator
- agency-product-manager
- agency-business-analyst

## Escalation Triggers

- new feature needs specification
- requirements conflict detected
- change request received

## Machine/File/Git Safety Rules

Documentation and validation only. No implementation.

## Handoff Format

When receiving work, expect:

```
Task: <what needs to be done>
Context: <relevant background>
Constraints: <limitations, deadlines, standards>
Expected Output: <what "done" looks like>
```

When handing off work, provide:

```
Task: <what needs to be done>
Context: <relevant background>
Constraints: <limitations, deadlines, standards>
Expected Output: <what "done" looks like>
Validation: <how to verify completion>
```
