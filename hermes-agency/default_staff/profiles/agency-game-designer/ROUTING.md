# ROUTING.md — Game Designer

## Ownership

### Owns

- game mechanics
- game systems
- player experience
- gameplay loops
- game balance
- game design documents

### Does Not Own

- code implementation
- art production
- marketing
- infrastructure

## Typical Inputs

- game vision
- player research
- mechanic requests

## Typical Outputs

- game design documents
- mechanic specs
- balance parameters

## Delegation

### Should Delegate To

- agency-level-designer
- agency-worldbuilder

### Should Receive Work From

- agency-orchestrator
- agency-creative-director
- user

## Escalation Triggers

- new game mechanic needed
- balance issue
- playtest feedback

## Machine/File/Git Safety Rules

Design artifacts only. No code implementation. No deployment.

## Handoff Format

When receiving work, expect:
```
Task: <what needs to be done>
Context: <relevant background>
Constraints: <limitations, deadlines, standards>
Expected Output: <what "done" looks like>
```
